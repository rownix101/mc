# 大视距网格优化

应用的整片网格请求现在复用后台线程中的区块网格缓存。缓存保存区块局部坐标；玩家移动时只重建新进入视距、LOD 改变和编辑影响到的区块，然后按原有顺序合并并转换到新的渲染原点。缓存随视距范围淘汰，避免沿途无限累积几何。

编辑快照的新增、修改、删除都会使相关区块失效。失效范围包含四格邻域，覆盖远景地表采样、近景面剔除、AO 和材质边缘混合所需的邻居。生成后的地形列也在后台世界中保留，近景构建不再创建世界并重复装饰树木。

近景面剔除使用包含一格边界的连续内存快照，避免为每个方块的六个面及 AO 采样反复查询世界哈希表。方块、透明面、纹理和 AO 的回归测试逐字节比较网格数据；缓存测试还覆盖原点变化、边界编辑及编辑撤销。

## 复现测量

```sh
cargo test --release --lib cached_view_mesh_benchmark -- --ignored --nocapture
```

本机一次独立运行，种子 `2026_0904`，半径 192 格：

| 场景 | 重建区块 / 缓存区块 | CPU 网格耗时 |
| --- | --- | --- |
| 首次请求 | 169 / 169 | 1.245 秒 |
| 相同位置再次请求 | 0 / 169 | 6.35 毫秒 |
| 从原点移动 8 格 | 0 / 169 | 4.42 毫秒 |
| 移动到 x=32，跨区块和 LOD 边界 | 41 / 169 | 187.68 毫秒 |

诊断最后添加远景编辑，并将缓存结果与不使用几何缓存的完整构建逐字节比较。后者在已有地形列的情况下耗时 2.383 秒。以上是单次 CPU 测量，受机器负载影响，不代表游戏帧率或 GPU 耗时。

## 当前限制

缓存增加一份视距内 CPU 几何的内存占用。当前仍需组装并上传完整 GPU 网格，首次生成和跨 LOD 边界仍有明显成本。GPU 侧已加入下述顶点压缩和可见性剔除。后续仍需测量 GPU 上传、阴影和主场景耗时，并考虑独立区块 GPU 缓冲与分帧上传。


## GPU 提交优化

GPU 使用独立的 80 字节顶点格式（CPU 网格仍为 104 字节）。法线、切线和副切线存为 `Snorm8x4`；当前体素面的轴对齐方向可精确表示。位置、UV、AO 和材质属性保持原精度。上传时复用暂存数组；减少的是传输字节和顶点读取带宽，实际缓冲分配仍按二次幂增长。

网格每 256 个面划为连续批次，上传时计算包围盒。每帧分别用主相机和阴影相机的裁剪矩阵剔除不可见批次，合并相邻可见索引范围，保留透明面的原始绘制顺序。纯水批次不提交阴影通道；混合批次保留原来的逐片元水面排除逻辑。水面包围盒包含顶点着色器波动的最大位移，避免边缘闪烁。

F3 的 GPU 区域显示实际主场景/阴影三角形数、draw call 数和上次网格上传字节数。

复现提交量诊断：

```sh
cargo test --release --lib full_view_gpu_submission_counts -- --ignored --nocapture
```

本机种子 `2026_0904`、192 格视距、相机 `(0,85,0)`、70° 垂直视角、16:9 画幅，共 193,884 个三角形：

| 观察方向 | 提交三角形 | draw calls | 相对完整提交减少 |
| --- | ---: | ---: | ---: |
| +X | 103,772 | 20 | 46.5% |
| -X | 70,656 | 20 | 63.6% |
| +Z | 88,412 | 15 | 54.4% |
| -Z | 53,248 | 13 | 72.5% |
| 正午阴影 | 102,748 | 1 | 47.0% |

该网格顶点数据从 40,327,872 字节降至 31,021,440 字节（减少 23.1%）；包括索引的上传量从 42,654,480 降至 33,348,048 字节（减少 21.8%）。这些是确定的提交量与传输量，不是 GPU 时间或 FPS 基准。

验证包含六个裁剪面、透视投影、跨裁剪面的包围盒、水波位移、纯水阴影排除和连续 draw 合并。实际 GPU 离屏测试使用生产着色器执行阴影、不透明和透明通道，读取像素对比完整提交与剔除提交；并与空几何画面对比，确保测试确实绘制了可见几何。

## 片元着色器优化（2026-09-10）

在已有顶点压缩和可见性剔除基础上，继续减少每个像素的工作量：

- 阴影 PCF 从 9 次双线性比较采样改为 4 次加权比较采样。利用原核每轴的 `(1-s, 1, 1, s)` 权重配对，保留原来的滤波覆盖范围、深度偏移和边界淡出，不降低阴影贴图分辨率。
- 材质边缘只读取权重大于零的邻居。一个有效邻居时，额外的颜色、法线、粗糙度读取从 12 次降到 3 次；两个邻居时降到 6 次。分支使用显式 UV 梯度，保留 mip 选择。
- 水面法线利用正弦差恒等式，把四次水位采样中的 16 次正弦改成 4 次余弦。预计算系数为 `amplitude * sin(frequency * direction * 0.08) / 0.08`，保留原来中心差分的平滑效果。不透明顶点也不再无条件求水波高度。

### GPU 时间戳基准

```sh
cargo test --release --lib fragment_gpu_benchmark -- --ignored --nocapture
```

本机 AMD Radeon RX 580 2048SP、Vulkan / RADV、Mesa 26.2.2，512×512 离屏目标，固定相机和时间。使用生产管线，绘制天空，并在不透明和透明管线各绘制一个可见三角形；比较保留原采样路径的参考着色器与优化版。时间戳只包围前向渲染通道，不包含阴影贴图生成、纹理上传、CPU 编译或像素回读。每种配置预热 2 帧，取后续 12 帧中位数。

| 合成负载 | 原着色器 GPU 时间 | 优化后 GPU 时间 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 材质边缘混合 | 0.1147 ms | 0.0995 ms | 13.3% |
| 水面 | 0.1107 ms | 0.0880 ms | 20.5% |

这是片元负载微基准，不是完整游戏帧率；实际收益取决于分辨率、画面中的水面和材质边缘比例、阴影覆盖及其他瓶颈。基准会将原版/优化版画面输出到 `target/gpu-performance/`，便于检查。无 GPU 或不支持时间戳查询时会明确打印跳过原因。

### 回归验证

`optimized_shader_preserves_material_blends_and_water` 使用独立采样参考着色器（间接光模型与生产版同步），分别比较普通材质、边缘混合和水面像素，允许每通道最多 2/255 的浮点量化差异，并验证可见性剔除前后像素一致、几何确实出现在画面中。`paired_shadow_taps_preserve_bilinear_kernel` 枚举 4×4 阴影比较结果的全部 65,536 种组合及四种子像素相位，检查合并采样与原核一致。

全功能 check、clippy（警告视为错误）、格式检查和全目标测试通过；release 测试为 101 通过、4 个诊断默认忽略。另行检查发现现有 `--no-default-features` 构建仍因 `src/app.rs` 无条件使用可选 egui 依赖而失败。
